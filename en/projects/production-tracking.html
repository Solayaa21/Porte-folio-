Video game localization studio, Paris · 2026

Production pipeline tracking, from intake to delivery

Every production step tracked and visualized, from the client script to delivery. To report to the client precisely, steer projects and price quotes on actual throughput.

The need

Production information was scattered: client scripts, tracking files per language copied across several servers, post-production folders cleared after each delivery. Nobody could say where each line of a project stood.

What I built

A Windows app that prepares the tracking files from the client script, a daily update that reads the servers without changing anything, and a Power BI dashboard that follows each line from recording to delivery.

What it changes

Project managers see real progress at a glance, know how many studio hours are left, and send the client a clear PDF view. Inconsistencies are flagged instead of being hidden.

The workflow, step by step
  1. Master Script BuilderMerges the client's scripts into one file without losing a line, and spots what changed from one version to the next.
  2. Audio Reference CheckerChecks that every reference audio file exists, in the folders or ZIP files sent by the client.
  3. Tracker BuilderCreates one tracking file per language, in the studio's format, ready for recording.
  4. Dashboard UpdateReads the tracking files and post-production folders every day, and remembers the steps already seen.
  5. Power BIOverview, script line by line, details, remaining files, data quality and client view.
Screens
Under the hood
  • Windows app in Python, PySide6 interface, delivered with no installation and no Python on the computer.
  • 138 automated tests. Tracking file creation was checked cell by cell against a hand-made file: 0 differences across 145,783 cells.
  • Read-only on the servers: no client file is ever changed, and an update in progress blocks the others.
  • Memory of the steps: what an update has seen stays known, even after post-production folders are cleared.
  • Power BI model generated by script: 11 tables, 56 DAX measures, versioned like the rest of the code.
  • Releases published with Git, each with its scope, its limits and a way back.
  • Guides included: one for project managers, one for the people who maintain the tool.
  • Built with generative AI (Claude Code, Codex) under my direction: choices, tests and validation.
